# MirrorDock 升级为安卓手机助手：功能与 UI 调研报告

> 调研日期：2026-11-24 · 基线版本：v0.4.27-beta · 性质：建议稿（未改任何代码）
> 事实来源：仓库 `src/App.tsx`、`DEVELOPMENT_TASKS.md`、产品规划与升级路线图；对标来自公开产品页与评测（ToDesk / 向日葵 / AirDroid / QtScrcpy / Microsoft Phone Link）。
> 所有升级建议都必须继续遵守 `AGENTS.md` 的产品红线：**本地优先、显式授权、可见可撤销、不绕过锁屏/DRM/MDM、不默认云录制或遥测**。

## 一、结论摘要（先看这里）

1. **MirrorDock 已经是"半个手机助手"**：镜像/控制、截图、录像、文件传输、APK 安装、通知镜像、多设备、桌面模式、伴侣 App、NAS 远程 Web 都已落地。缺的不是连接能力，而是**"设备资产"维度的管理能力**（应用、照片、短信、存储、电量、定位类信息）与**统一的设备卡片首页**。
2. **最高性价比的三件事**：① 设备中心首页（多设备卡片 + 状态聚合）；② 应用管理（列表/卸载/导出/批量安装）；③ 相册与文件浏览器（缩略图流 + 按类型筛选）。三者都能复用现有 ADB 通道与"固定参数直调"架构，不引入新权限模型。
3. **UI 应升级为"双栏设备工作台"**：左侧设备列表面板 + 右侧当前设备工作区，顶部一条设备状态栏。这是 ToDesk / 向日葵 / AirDroid 三家共同验证过的信息架构，与现有 ToDesk 风格一脉相承，改动可控。
4. **不建议跟进的能力**：远程拨打/接听电话、读取短信正文、远程清除数据、摄像头麦克风远程监听。前两项涉及高敏个人通信内容，后两项越过"不绕过用户同意"红线或需要 MDM 授权——做了会破坏产品的核心信任承诺。
5. **本轮是调研，不是实现**。下面的功能按 P0/P1/P2 分级，UI 给出可对照的原型方向；排序与取舍由产品负责人拍板后再进入开发台账。

## 四、功能升级建议（按优先级）

### P0：设备中心与资产管理（建议优先做）

| # | 功能 | 用户价值 | 实现路径与边界 |
|---|---|---|---|
| F1 | **设备首页（设备卡片墙）** | 打开软件先看到"我的手机们"，每台一张卡：型号、电量、存储、连接状态、通道（USB/无线）、上次镜像时间；点卡片进入该设备工作区 | 复用现有设备枚举 + `adb shell dumpsys battery`/`df` 只读命令；电量存储是只读信息，不写不授权 |
| F2 | **设备备注 / 分组 / 收藏** | 多设备时不再靠序列号辨认（X10-88 已有备注基础） | 前端 localStorage 扩展；不上传 |
| F3 | **设备健康状态** | 把散落的诊断聚合成"可镜像/需授权/离线/配对中"四态，对应到卡片颜色 | 复用 `capabilitySummary` 与状态机，不新增协议 |

### P1：手机管理核心功能（助手化的实质内容）

| # | 功能 | 用户价值 | 实现路径与边界 |
|---|---|---|---|
| F4 | **应用管理** | 列表已装应用（用户/系统分区）、搜索、按占用排序、卸载第三方应用、导出应用清单 CSV | `adb shell pm list packages` / `pm uninstall --user 0`；卸载必须逐次确认；**不预装、不静默** |
| F5 | **相册与文件浏览器** | 缩略图流浏览 DCIM/下载目录、按日期/类型筛选、批量勾选取回到电脑、自动按日期建文件夹 | 复用 `/files` 静态服务与 ADB pull；缩略图先取小尺寸；受保护图片仍遵守黑屏边界 |
| F6 | **批量安装 APK** | 一次选多个 APK 顺序安装，逐个回执（当前只装第一个并提示） | 扩展 X10-63 拖拽逻辑为队列；每包仍需手机确认 |
| F7 | **设备信息页** | 型号/Android 版本/ROM/分辨率/存储/电量/已用时长，一键复制诊断摘要 | 只读 `dumpsys`/`getprop`；用于客服与兼容性反馈 |

### P2：体验与粘性增强

| # | 功能 | 用户价值 | 实现路径与边界 |
|---|---|---|---|
| F8 | **通知中心升级** | 通知持久化到本机加密存储（默认关）、按应用白名单筛选、点击跳转到对应会话 | 当前仅内存 50 条；持久化需新增本地加密与过期清理，属隐私敏感改动，需单独评审 |
| F9 | **游戏按键映射** | 把键鼠映射为手机触控点，对标 QtScrcpy；游戏场景差异化 | scrcpy 4.1 有 `--mouse-bind` 但映射复杂，工作量大；建议先做 vendored 方案可行性评估 |
| F10 | **投屏演示模式** | 镜像窗口叠加激光笔/画笔批注，适合教学与会议演示 | 纯前端 overlay，不改视频管线，低风险 |
| F11 | **定时/条件录制** | 按时间或设备状态自动开始/结束录制，配合 NAS 常开机场景 | NAS 侧已有 headless 录制与归档策略（X10-114），扩展调度即可 |
| F12 | **操作回放与脚本** | 记录键鼠操作序列并回放，用于重复测试和演示 | 需评估是否触碰"无人值守通用控制"红线；**默认不启用、逐次确认** |

### 明确不建议（红线）

- **读取/发送短信正文、拨打电话**：个人通信内容，超出"镜像与控制"授权范围，且伴侣 App 申请 SMS/CALL 权限会显著降低商店过审与用户信任。
- **远程清除数据 / 找手机 / 设备管理员激活**：需 MDM 或设备管理器权限，与 `AGENTS.md` "不绕过 MDM、不无人值守"直接冲突。
- **默认开启的摄像头/麦克风远程监听**： scrcpy 摄像头源虽支持，但必须默认关闭、逐会话显式开启并可见提示。
- **云端中继与账号体系**：引入账号即引入云存储与遥测假设，破坏"本地优先"根基。

## 五、UI 升级方案

### 5.1 信息架构：从"功能页签"到"设备工作台"

当前：左侧 5 个页签（连接 / 工具 / 无线 / 设置 / 帮助），用户需在页签间跳转找功能。
建议：**双栏结构 = 左侧设备栏 + 右侧设备工作区**，顶部一条跨设备状态栏。

```
┌──────────────────────────────────────────────────────────────┐
│ MirrorDock   [全部设备 3]  [USB 首选]  [通知 2]  [设置] [?] │  顶栏
├─────────────────┬────────────────────────────────────────────┤
│ 我的设备        │  Redmi K40 · M2104K10AC        [开始镜像] │  设备标题条
│ ● 小狸 (USB)    │  Android 13 · 电量 78% · 存储 64/128GB    │
│ ● 平板 (无线)   ├────────────────────────────────────────────┤
│ ○ 备用机(离线)  │  ┌────────┐ ┌────────┐ ┌────────┐         │
│                 │  │ 截图   │ │ 录像   │ │ 文件   │         │  工具宫格
│ [+ 添加设备]    │  └────────┘ └────────┘ └────────┘         │
│                 │  ┌────────┐ ┌────────┐ ┌────────┐         │
│ 最近会话        │  │ 应用   │ │ 相册   │ │ 通知   │         │
│ · 小狸 2h前     │  └────────┘ └────────┘ └────────┘         │
│ · 平板 昨日     │                                            │
├─────────────────┤  传输任务 / 最近截图（可折叠）             │
│ 仅在本机连接    │                                            │
└─────────────────┴────────────────────────────────────────────┘
```

**为什么这样改**：
- 设备成为一等公民——对标 ToDesk 的"我的设备"列表、AirDroid 的设备选择器，用户心智从"我要用某个功能"变成"我要操作某台设备"。
- 工具宫格把原本分散在 3 个页签的功能聚合，减少跳转。
- 状态栏聚合通知数、设备数、通道，避免每个面板各说各话。

### 5.2 视觉语言：保留蓝色主色，升级为"设备卡片 + 状态语义色"

| 维度 | 现状 | 建议 | 理由 |
|---|---|---|---|
| 主色 | `#2e6be6` 蓝（品牌渐变） | 保留 | 品牌一致性，不推翻既有认知 |
| 背景 | 浅灰 + 白卡 | 保留 + 增加卡片层级阴影（轻） | ToDesk/向日葵都用浅色工作台 |
| 状态色 | 单一文字标签 | 绿=就绪/USB、蓝=无线已连、橙=配对中、灰=离线 | 一眼识别设备可用性（对标 ToDesk 在线圆点） |
| 设备卡 | 无（列表式） | 大卡片：设备名 + 型号小字 + 状态点 + 电量条 | AirDroid/Phone Link 共性 |
| 工具入口 | 文字面板标题 | 图标 + 标题 + 一行说明的宫格卡 | 手机助手的典型"功能矩阵" |
| 设备标题条 | 分散在连接页 | 固定在工作区顶部，含主操作按钮 | 减少"开始镜像要去找" |
| 深色模式 | 无 | P2 可选 | 成本主要在 CSS 变量化，非必须 |

### 5.3 交互原则（沿用既有铁律）

- **每个功能入口都显示前置条件**：不是"截图"灰掉，而是"先连接手机"——复用 X10 现状的错误语义。
- **会话状态可见可撤销**：录制、传输、通知镜像在状态栏有常驻指示，点击可停止。
- **不暴露原始 ADB/编码细节**作为主路径；诊断信息折叠在"详情"里。
- **导航切换不丢状态**：现有"面板常驻 + CSS 显隐"模式要保持。

## 七、实施路径建议（分阶段，每阶段可独立验收）

| 阶段 | 内容 | 验收标准 | 风险 |
|---|---|---|---|
| **阶段 A：设备中心** | F1 设备卡片墙 + F2 备注 + F3 健康状态；UI 双栏重构 | 三台设备同时显示、状态准确、切换不丢状态；`pnpm build` + vitest | 中：前端重构大，需保持面板常驻模式 |
| **阶段 B：本地管理** | F4 应用管理 + F5 相册/文件 + F7 设备信息 | 真机：列应用、卸载一个第三方应用（用户确认）、取回照片、复制诊断摘要 | 中：ADB 只读命令为主，卸载需强确认 |
| **阶段 C：粘性增强** | F6 批量安装 + F8 通知持久化 + F10 演示批注 | 真机：三个 APK 顺序安装回执、通知开关与过期清理、批注 overlay | 高：通知持久化涉及隐私，需单独评审 |
| **阶段 D：可选** | F9 按键映射 + F11 定时录制 + F12 操作回放 | 单独拍板，触碰红线则不做 | 高：F12 需红线复核 |

## 八、待产品负责人拍板的决策点

1. **UI 改造范围**：是否接受"双栏设备工作台"重构（阶段 A），还是只在现有 5 页签内做增量优化？
2. **助手化深度**：P1 的 F4 应用管理 / F5 相册是否进入下一版本？二者是"助手"与"镜像工具"的分水岭。
3. **通知持久化**：F8 是否立项？如果做，本机加密存储 + 默认关闭 + 30 天过期是否可接受？
4. **游戏按键映射**：F9 是否值得投入（对标 QtScrcpy）？需要先做可行性评估再定。
5. **红线确认**：第四节"明确不建议"清单是否保持？特别是短信/通话与远程清除——这是与 AirDroid 拉开差距的关键取舍。
