# MirrorDock v0.4.23-beta

## 修复与增强

### 录制状态卡死自愈（X10-105）

在 Windows 上录制一段时间后录制进程被系统/链路掐断时，托盘菜单仍停在「结束屏幕录制」、点结束文案不变、再点开始提示「已在录制」——三处状态全卡死。根因是后台只监测镜像显示进程，独立录制进程一旦自己闪退就无人回收句柄。

本版在显示会话存活期间顺带监测录制进程，发现它异常退出就自动复位到「开始录制」，托盘、按钮、删除校验三处状态同步恢复，不再卡死。

### 断连自动续录（X10-107）

无线连接下链路周期性断连会把录制掐断（此前每段只能录几分钟）。本版在镜像断连自动重连成功后，自动用**分段文件名**续录（`录屏.mp4` → `录屏-part2.mp4`、`part3`…），断连期间的画面如实不补回。

- 连续断连 3 次后放弃续录，并提示改用数据线——无线链路持续抖动时，无限重试只会切出一堆碎片。
- 你手动开始新一轮录制时，此前的断连续录计数自动清零。
- 续录失败不会拖垮刚恢复的镜像，可手动重开。

### 镜像退出诊断日志（X10-108）

此前镜像进程被断连杀死时，诊断日志里只有「启动成功」、没有任何退出记录，排查只能靠回忆复现。本版起，镜像进程无论正常还是异常退出（不限平台），都会记录一条退出事件：退出性质、是否触发自动重连、scrcpy 输出末尾。之后任何平台的异常退出都能在「帮助与诊断」里直接看到证据。

## 实测验证

- 桌面端 cargo 测试 204 全绿、静态检查零告警、前端类型检查通过。
- USB 有线录制 13 分钟稳定不断连（用户实测）。
- 断连续录的端到端（重连→自动起新录制进程）与「桌面模式虚拟屏断连自动重连」待真机复核——新版已内置退出诊断日志，复现后导出即可定位。

## 升级

- **自动更新**：打开应用按提示升级到 0.4.23。
- **手动安装**：从 Release 资产下载对应平台安装包覆盖安装即可。
- **完整性**：四平台安装包均带 Ed25519 签名校验，更新通道安全。

## 无线录制建议

断连的根因是无线链路（Wi-Fi 漫游/省电踢人），非程序问题。要稳定长时间录制，建议：

1. 优先用 **USB 数据线**连接（实测 13 分钟不断）。
2. 无线方案下：手机「设置 → WLAN → 高级」关闭 Wi-Fi 省电/智能切换；路由器关闭 band steering / 漫游引导，把手机固定在单一 AP 与频段。
