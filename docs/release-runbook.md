> 面向 MirrorDock 的发布值守。每次发布照此执行；任何一步证据缺失即停。

## 发布流程

1. **RC 打标**：`vX.Y.Z-rc.N` → CI 四平台打包 + verify；制品含 SHA256SUMS 与 `-meta`。
2. **真机验证**：下载 CI 制品（不用本地构建冒充），在至少一台授权真机上完成：安装（不设任何环境变量，验证随包 scrcpy/adb 生效）→ USB 镜像 → 无线镜像 → 录制收尾 → 截图/传输。
3. **正式打标**：`vX.Y.Z` → CI 产出正式制品；发布说明必须包含：已知限制（诚实清单）、SBOM/哈希、签名状态（未签名要写明）。
4. **发布后值守**：发布后 72 小时内盯支持渠道；诊断包是第一手材料（用户显式导出后提供）。

## 回滚决策

- **触发**（任一）：安全级缺陷（数据离开本机、子进程执行非预期内容）；崩溃率异常；真机验证失败但已发布。
- **动作**：下架当前版本下载链接 → 恢复上一版本及其 SHA256SUMS → 发布公告说明影响与操作（重装旧包；用户数据目录向后兼容，旧包读新数据以 schema 版本号为准——schema 迁移必须带回退策略，否则禁止发布）。
- **记录**：每次回滚在 DEVELOPMENT_TASKS.md 留痕（原因/影响版本/恢复版本/遗留风险）。

## 版本与兼容性记录

- 版本格式：semver；`v0.1.0-alpha.1` 为首个四平台打包验证版（制品体积证实随包 scrcpy 生效）。
- 兼容性矩阵维护在 docs/compatibility-matrix.md，发布时同步到公开「兼容性页」。
