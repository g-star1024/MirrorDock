# 许可证运营手册（内部文档，勿外发）

面向操作者：需要给付费/测试用户签发 MirrorDock Pro 激活码的内部成员。

## 1. 密钥管理（红线）

- 签发私钥种子保存在**仓库外**的内部文档目录 `mirrordock-license-signing-key.txt`。
- 绝不进 Git、绝不进 CI、绝不在对话/日志/截图中回显。
- 对应公钥编译进客户端二进制（`src-tauri/src/lib.rs` 的 `LICENSE_VERIFYING_KEY`）。
- 私钥泄露的处置：重新生成密钥对 → 新公钥随新版本发布 → 旧版本逐步淘汰（v1 无远程吊销，见 §5）。

## 2. 签发一条激活码

```sh
cd src-tauri
SEED=$(grep -Eo '[0-9a-fA-F]{64}' "<内部目录>/mirrordock-license-signing-key.txt" | head -1)
MIRRORDOCK_LICENSE_SEED="$SEED" cargo run --example license_sign -- \
  --key-id 2026-0001 --edition pro --days 365
# --days 0 表示永久
```

- **key-id 规范**：`<年份>-<订单/客户序号>`（如 `2026-0001`）。它显示在用户 GUI 的
  「版本与授权」里，是唯一能用来对账的标识，务必与订单记录一一对应。
- **有效期**：年付 `--days 365`；买断 `--days 0`；试用装建议 `--days 30`。
- 输出即激活码全文（`MD1-XXXXXX-…`），直接复制交付。

## 3. 交付与用户激活

1. 通过邮件 / IM 把激活码**全文**发给用户（一行，勿拆行）。
2. 用户操作：客户端 → 设置 → 版本与授权 → 粘贴 → 「激活专业版」。
3. 激活完全离线：不需要联网验证，没有服务器参与。激活状态保存在本机应用数据目录。

## 4. Beta 内置码（当前状态）

- `v0.2.0-beta` 起，客户端内置了一条**永久测试码**（key-id `beta`）：
  未激活的安装首次启动会自动激活，所有用户体验完整功能。
- 用户显式「撤销本机授权」后不再自动激活（尊重选择）。
- **退出 Beta 时必须移除** `BETA_LICENSE_KEY` 常量；已激活的 beta 码因永久仍有效，
  如需回收见 §5。

## 5. 诚实边界：v1 做不到什么

- **无远程吊销**：许可证是离线验签的，一旦激活，服务器（如果以后有）无法让单台
  设备的已激活状态失效。
- **续费 = 换码**：到期后给用户签一条新码（key-id 加后缀，如 `2026-0001-r2`），
  用户重新粘贴激活即可覆盖旧状态。
- **大规模泄露的兜底**：换钥发新版是唯一硬手段；这也是正式版许可证建议带
  `--days` 有效期而不是永久的原因——即使换钥不及时，旧码也会自然过期。
