Capability differences by Android version

These differences come from scrcpy's official docs and were checked against the local binary. They are platform capability boundaries, not MirrorDock defects, and are never bypassed.

App-level limits: no call audio, and some copyright-protected apps may be silent or black. The system requires an unlocked device when mirroring starts (prerequisite for audio capture). These behaviors are explained in the UI.

Known limitations

Honest list: these entries change with releases and never quietly disappear.

  • ✓ In-app automatic updates (since v0.3.0) Updates are installed only after minisign signature verification. Note: clients at v0.4.0-beta and earlier have a broken update endpoint and need one manual upgrade from the release page; fixed since v0.4.1.
  • ✓ Installers are not code-signed Until signing is in place, macOS shows Gatekeeper and Windows shows SmartScreen warnings. See the homepage FAQ and download page for what to do.
  • ✓ Only USB and same-LAN wireless are supported No cross-subnet, NAT traversal, or server relay. Video and files only flow between your own devices.
  • ✓ Linux packages need runtime libraries from your distro Since v0.3.0 Linux packages bundle scrcpy 4.1 (compiled from official source; adb is also the official platform-tools binary). But the SDL3 and FFmpeg shared libraries scrcpy 4.x needs are not bundled — your system must provide them. Ubuntu 25.04+ can install them directly; 22.04 / 24.04 need to build SDL3 first — see the "Linux runtime libraries" section of the repository README.
  • ✓ Black protected content and silent calls are platform behavior Enforced by Android (FLAG_SECURE / audio capture policy). No tool can or should bypass it; the UI explains this honestly.
  • ✓ No cloud sync, no telemetry Diagnostics can be previewed before export, with device serials, pairing codes and file paths stripped. Nothing is uploaded automatically.
